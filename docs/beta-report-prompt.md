# 베타 리포트 프롬프트

베타 테스터가 **자기 Daat 채팅창에** 그대로 붙여넣는 프롬프트입니다.

만든 사람에게 분석 도구가 없으므로, 실사용을 알 수 있는 유일한 경로는 테스터 본인의
에이전트가 자기 볼트를 보고 보고하는 것입니다. 그래서 두 가지가 프롬프트 안에 박혀
있습니다: **노트 내용은 절대 나가지 않는다**는 것과, **보내기 전에 본인이 먼저 읽는다**는 것.

전달할 때 한 줄만 덧붙이면 됩니다:
"Daat 채팅에 이거 붙여넣고, 나온 결과 읽어보고 괜찮으면 보내주세요. 이상하면 지우고
보내셔도 됩니다."

---

## 프롬프트 (여기부터 복사)

```
아래 내용을 조사해서 개발자에게 보낼 리포트를 만들어 줘.

**규칙 — 반드시 지켜:**
- 내 노트의 *내용*은 쓰지 마. 제목도 쓰지 마. 개수, 날짜, 폴더 이름, 패턴만 써.
- 사람 이름, 회사 이름, 금액, 이메일 주소는 절대 쓰지 마.
- 확실하지 않으면 "모르겠음"이라고 써. 추측해서 채우지 마.
- 다 쓰고 나서 마지막에 "위 내용에 개인정보가 없는지 확인해 주세요"라고 한 줄 붙여.

**1. 시작할 때**
- 설치하고 처음 쓰기 시작할 때까지 막혔던 곳이 있었는지 (기억나는 대로)
- 첫 질문 두 개에 답했는지, 아니면 건너뛰었는지
- 지금 어떤 모델을 쓰고 있는지

**2. 실제로 뭘 하는지**
- 볼트에 노트가 몇 개, 폴더는 어떤 게 있는지 (`vault_list`)
- 그중 내가 직접 쓴 것 대 네가 쓴 것의 대략적인 비율
- 화면 중에 실제로 쓰는 것과 한 번도 안 열어 본 것
  (노트 / 할 일 / 캘린더 / 회의 / 메일 / 가계부 / 그래프)
- 주로 쓰는 언어 (한국어 / 영어 / 섞어서)
- 하루에 대략 몇 번 여는지, 한 번에 얼마나 오래 쓰는지

**3. 볼트가 실제로 "두 번째 뇌" 역할을 했는지 — 이게 제일 중요해**
- `Inbox/` 폴더가 있는지, 있으면 노트가 몇 개인지
- 그 안의 항목이 실제로 쓸모 있었는지, 아니면 잡동사니였는지 (개수로, 대략 몇 대 몇)
- 네가 시키지 않았는데 노트를 쓴 적이 있는지, 몇 번쯤인지
- 내가 예전에 말한 걸 네가 기억해서 답한 적이 있는지 — 있으면 몇 번쯤
- 반대로, 볼트에 있는데 네가 못 찾아서 내가 다시 설명한 적이 있는지

**4. 눈에 보이는 고장 — 파일로 직접 확인해 줘**
- 이름에 `(conflict` 가 들어간 파일이 있는지, 몇 개인지
- 내용이 완전히 빈 `.md` 파일이 있는지, 몇 개인지
- 이름이 `.` 으로 시작하고 `.tmp-` 가 들어간 숨은 파일이 있는지
- 열었더니 내용이 비어 있거나 "iCloud에서 내려받는 중"이라고 나온 적이 있는지
- 저장이 안 된다는 메시지를 본 적이 있는지
- 앱이 멈추거나 꺼진 적이 있는지, 그때 뭘 하고 있었는지

**5. 안 되거나 기대와 달랐던 것**
- 시켰는데 못 한 것
- 됐지만 결과가 틀렸거나 이상했던 것
- "이건 당연히 될 줄 알았는데" 안 됐던 것
- 다른 앱으로 돌아가서 한 일이 있는지, 뭘 하러 갔는지

**6. 마지막**
- 딱 하나만 고칠 수 있다면 뭘 고쳐야 할지
- 이 앱을 계속 쓸 것 같은지, 안 쓸 것 같으면 왜인지
- 남한테 추천할지

각 항목은 짧게. 없으면 "없음"이라고만 써.
```

## 이 답으로 무엇을 할 수 있는가

항목마다 실제로 고칠 수 있는 것과 연결해 뒀습니다. 답이 와도 손댈 게 없는 질문은
넣지 않았습니다.

| 답 | 하게 될 일 |
|---|---|
| `Inbox/`가 없다 | 자동 정리가 한 번도 안 돌았다는 뜻. 트리거가 세션 종료라 실제로는 거의 안 도는 것. 턴 단위나 시간 단위로 옮겨야 함 |
| Inbox는 있는데 대부분 잡동사니 | 필터 프롬프트가 느슨한 것. `_FILING_PROMPT`를 조이고, 빈 배열이 정상이라는 걸 더 강하게 |
| "기억해서 답한 적 없음" | 리콜이 작동은 하는데 쓸모가 없다는 것. 검색어 추출이나 `MAX_RECALL_NOTES`를 봐야 함 |
| "볼트에 있는데 못 찾음" | 리콜 실패 사례. 어떤 말로 물었는지만 알면 토크나이저를 고칠 수 있음 |
| `(conflict` 파일이 있다 | iCloud 동시 편집이 실제로 일어났다는 것. 충돌 UI가 충분한지 봐야 함 |
| 빈 `.md`가 있다 | **최우선.** 오늘 고친 데이터 손실이 그 사람 기계에서 이미 일어났다는 증거 |
| `.tmp-` 숨은 파일 | 쓰기 실패 흔적. 오늘 누수는 막았지만 이전 빌드 잔재일 수 있음 |
| 안 열어 본 화면이 있다 | 그 화면을 지우거나, 발견되게 만들거나. 여섯 개 다 보이는데 둘만 쓴다면 사이드바가 과함 |
| 첫 두 질문을 건너뛰었다 | `SOUL.md`가 안 써졌다는 뜻. 건너뛴 사람에게 기본 페르소나를 넣을지 결정해야 함 |
| 한국어로 쓴다 | 오늘 고친 한국어 리콜이 실제로 그 사람에게 닿는지 확인 |
| 저장 실패 메시지를 봤다 | 어떤 상황이었는지가 곧 재현 조건 |

## 한계 — 알고 받아야 하는 것

- **한 명은 한 명입니다.** 이걸로 알 수 있는 건 그 사람의 사용이지 경향이 아닙니다.
  세 명쯤 되면 겹치는 게 신호입니다.
- **에이전트도 틀립니다.** 3번의 "몇 번쯤"은 추정치입니다. 4번의 파일 확인만 사실입니다 —
  그건 실제로 디스크를 보고 세는 것이니까요.
- **프롬프트를 주는 순간 그 사람의 사용이 바뀝니다.** 리포트를 만들려고 평소 안 열던
  화면을 열어 볼 수 있습니다.
- **안 쓰는 사람은 답장하지 않습니다.** 가장 알고 싶은 사람이 가장 답을 안 줍니다.
